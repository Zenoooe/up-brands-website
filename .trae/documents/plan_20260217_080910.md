# Performance Optimization Plan: Fix Slow Initial Load

The "stuck on loading" issue is likely caused by the aggressive code splitting (`manualChunks`) and the heavy synchronous font imports introduced in the previous step. The browser is struggling to download and parse the large number of chunks and font CSS files before it can render the React app.

## Root Causes
1.  **Over-Splitting**: The `manualChunks` configuration created too many small files or suboptimal bundles, increasing HTTP request overhead.
2.  **Blocking CSS**: Importing **12 different font weight CSS files** in `main.tsx` blocks the main thread.
3.  **Supabase Connection**: The loading spinner persists until data is fetched. If the initial JS bundle is delayed, the data fetch starts later.

## Solutions

### 1. Simplify Code Splitting (Revert to Vite Default)
Vite's default chunking strategy is highly optimized. We will remove the complex `manualChunks` logic from `vite.config.ts`. This allows Vite to automatically balance chunk sizes based on the dependency graph, which is usually faster for SPAs.

### 2. Optimize Font Loading
Instead of importing every single weight (100-900) in `main.tsx`, we will only import the **essential weights** used in the design:
*   **Inter**: 400 (Regular), 700 (Bold), 900 (Black - used for "UP-BRANDS").
*   **Noto Sans SC**: 400 (Regular), 700 (Bold).
*   *Action*: Remove unused imports from `main.tsx` to reduce the CSS bundle size.

### 3. Preconnect & DNS Prefetch
We will ensure `index.html` has `dns-prefetch` for the Supabase domain (`supabase.co`) to speed up the initial data connection.

## Execution Steps
1.  **Modify `vite.config.ts`**: Remove `manualChunks`.
2.  **Modify `src/main.tsx`**: Reduce font imports to only essential weights.
3.  **Modify `index.html`**: Add `<link rel="dns-prefetch" href="https://<YOUR_SUPABASE_PROJECT>.supabase.co">`.
