# SEO & Indexing Troubleshooting Plan

The core issue is that Bing has "Discovered but not crawled" your site. This often happens with Single Page Applications (SPAs) like yours because when the crawler visits, it sees an empty `<div id="root"></div>` and may decide the page has "no content" before the JavaScript loads.

The previous error logs ("Duplicate tags", "Title too long") were from a tool scanning your *local* or *cached* version, or simply flagging the conflict between static HTML and dynamic React tags. But for *indexing*, having **some** static content is critical.

## 1. The "Skeleton" Strategy (Crucial for SPAs)
We will inject a minimal, static version of your homepage content directly into the `<div id="root">` in `index.html`.
*   **What this does**: When Bing/Google hits your URL, they immediately see text ("Up-Brands", "Brand Strategy", "GBA") in the raw HTML response, even if they don't run JavaScript.
*   **User Experience**: Real users will see this for a split second before React loads (reducing white screen time), then React takes over and replaces it.
*   **Content**: We'll add your Logo/Header text and the main H1/H2 taglines.

## 2. Robots.txt & IndexNow Verification
*   **Robots.txt**: We will verify it allows all major bots.
*   **IndexNow**: The key has been updated and submitted. We will assume this part is correct, but the *content* issue is blocking the actual crawl.

## 3. Execution Steps
1.  **Modify `index.html`**:
    *   Keep the static `<title>` and `<meta>` tags (restored in the last step).
    *   **New**: Add static HTML content inside `<div id="root">...</div>`.
    *   **Cleanup**: Ensure no conflicting hidden H1s are outside the root.
2.  **Verify**: Check that the raw source code contains readable text.
3.  **Deploy**: Push to production.

This "Prerendered Shell" approach is the standard fix for "Discovered - currently not indexed" errors on React apps hosted on standard servers.
